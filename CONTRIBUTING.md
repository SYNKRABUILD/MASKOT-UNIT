# Contributing to Maskot Unit

Thank you for your interest in contributing to Maskot Unit! This document provides guidelines and instructions for contributing to the project.

## Code of Conduct

- Be respectful and professional
- Provide constructive feedback
- Support fellow contributors
- Focus on the platform's mission: empowering content creators

## Getting Started

1. **Fork the Repository**
   ```bash
   git clone https://github.com/SYNKRABUILD/MASKOT-UNIT.git
   cd MASKOT-UNIT
   ```

2. **Create a Feature Branch**
   ```bash
   git checkout -b feature/your-feature-name
   ```

3. **Make Your Changes**
   - Follow coding standards
   - Write clear, descriptive commit messages
   - Keep commits atomic and focused

4. **Test Your Changes**
   - Ensure all tests pass
   - Test locally before pushing
   - Add tests for new features

5. **Submit a Pull Request**
   - Provide a clear description of changes
   - Reference related issues
   - Follow the PR template

## Commit Message Guidelines

```
[TYPE] Brief description (50 chars max)

Detailed explanation of changes (wrap at 72 chars)

Related Issues: #123
```

### Commit Types
- `feat:` New feature
- `fix:` Bug fix
- `docs:` Documentation update
- `style:` Code style changes (formatting, etc.)
- `refactor:` Code refactoring
- `test:` Test additions or updates
- `chore:` Build, dependency updates, etc.

## Coding Standards

### General Principles
- Write clean, readable code
- Comment complex logic
- Follow DRY (Don't Repeat Yourself) principle
- Use meaningful variable and function names

### Frontend
- Follow component-based architecture
- Use consistent styling approach
- Implement responsive design
- Ensure accessibility (WCAG 2.1)

### Backend
- RESTful API design
- Proper error handling
- Input validation
- Security best practices

## Pull Request Process

1. **Create PR with descriptive title**
2. **Link related issues** using `Closes #123`
3. **Describe changes clearly**
4. **Ensure CI/CD passes**
5. **Request review from team members**
6. **Address feedback promptly**

## Reporting Issues

When reporting bugs:
- Describe the issue clearly
- Include steps to reproduce
- Provide expected vs. actual behavior
- Attach screenshots if applicable
- Note your environment details

## Feature Requests

When suggesting features:
- Explain the use case
- Describe benefits to creators
- Suggest implementation approach
- Consider performance impact
